# DSHA 短线仓位管理插件

把用户确认的本机持仓快照、账户资金、市场环境和个股研究结论整理成仓位计划。支持截图识别后的待确认导入、总仓位与单股调整建议、新机会试探仓和满足条件后的分阶段增仓。

## 能力与边界

- **截图或文字导入**：由 DSHA 识别持仓后调用 `position_import_stage` 暂存草稿；调用 `position_import_review` 检查代码、数量、成本、可卖数量、资金日期和将被替换的记录；用户核对并明确确认后才调用 `position_import_confirm`。
- **持仓快照**：持仓保存在手机本机 SQLite。插件不登录券商，不读取券商实时账户。
- **风险参数**：首次使用时，由用户设置单笔风险预算、组合总风险上限、总仓位上限、单股/行业上限、不同市场状态的目标暴露、试探仓风险比例。插件不会替用户设定个性化风险百分比。仓位数量和持有期限遵守插件上限：最多 2 个同时持有标的，持有期限不超过 3 个交易日。
- **仓位计划**：`position_rebalance_plan` 返回组合暴露、现有持仓减仓/退出建议、机会试探仓与条件增仓阶段。新机会必须带入场价、低于入场价的止损、失效规则和有来源的研究证据。增仓阶段只作为条件计划，不代表信号已触发。
- **两种输出**：`mode: "summary"` 适用于多个插件协作；`mode: "detailed"` 展示单股依据、风险、来源与条件。
- **计划与实盘分离**：计划不会更改当前持仓，也不会提交、修改或撤销订单。用户实际成交后，再确认导入新的持仓快照。

## 首次配置顺序

1. 在 DSHA 中安装插件并启用工具。
2. 建议先把券商持仓截图或文字交给 DSHA 识别。让它逐项列出证券代码、名称、数量、可卖数量、成本、价格或市值；不确定的行应列为未识别项，不要猜。
3. 调用 `position_import_stage` 暂存，再调用 `position_import_review` 检查。选择 `replace` 会移除草稿中没有的旧持仓；只有在确认这是完整账户持仓时才使用。部分截图建议用 `merge`。
4. 用户核对后才调用 `position_import_confirm`，并按要求确认低置信度或未识别行。
5. 用 `position_account_state_set` 设置最新总权益和可用资金，或在导入草稿时带入账户摘要。
6. 用 `position_risk_profile_set` 设置并确认个人风险预算和目标仓位区间。
7. 每次计划先收集有日期和链接的市场、个股证据及止损依据，再调用 `position_rebalance_plan`。
8. 成交后更新持仓/资金快照，再生成下一份计划。

## 各工具

| 工具 | 用途 |
| --- | --- |
| `position_import_stage` | 暂存截图 OCR、文字解析或手动输入的持仓草稿。 |
| `position_import_review` | 查看草稿、缺失字段、识别数量和替换影响。 |
| `position_import_confirm` | 明确确认后写入本机持仓。 |
| `position_snapshot` | 读取本机确认过的持仓、资金与风险参数。 |
| `position_account_state_set` | 手动更新账户权益与可用资金快照。 |
| `position_risk_profile_set` | 保存用户确认的风险预算和仓位上限。 |
| `position_rebalance_plan` | 生成摘要或详细仓位计划，不执行交易。 |
| `position_plan_history` | 查看历史计划快照。 |
| `position_manager_status` | 查看持仓、资金、风险参数和待确认导入状态。 |

## 计算规则

- 计划使用 100 股整数手。现有仓位按用户设定的市场状态暴露目标、单股上限、行业上限和风险预算计算。
- 新机会先根据试探仓风险预算、止损距离、可用资金、组合暴露、单股/行业上限和持仓名额计算数量。
- 条件增仓阶段必须指定触发价、止损、条件描述和风险占比；只在触发并重新核对可用资金后由用户决定是否执行。不会因价格下跌而摊平。
- 缺少最新价格、市值、止损、权益或可用资金时，会降低覆盖率或停止精确数量/新开仓计算。旧行情不能用于精确股数。
- A 股 T+1、涨跌停、停牌、跳空、滑点与手续费会影响实际退出；风险预算是按假设止损成交的估算，不是最大亏损保证。
- 输入的行情和分析应注明日期及 HTTPS 来源。插件只验证格式和日期，不会自行证明来源内容真实。

## 本机存储

SQLite 数据库位于：

```text
~/.local/share/dsh-short-term-position-manager/short-term-positions.sqlite
```

持仓、账户快照、风险配置和计划历史只保存在设备本机。请勿把真实持仓文件、数据库或券商截图提交到 GitHub。

## DSHA 工作区提示词建议

将下面内容放入“短线仓位管理”工作区的 Markdown 指令中：

```markdown
# 短线仓位管理

你负责组合风险和仓位计划。先用 position_manager_status 检查配置；缺少真实持仓、账户资金或用户风险参数时，明确列出缺项，不编造。

用户给出截图或文字持仓时，先提取结构化字段并展示核对清单；通过 position_import_stage 暂存并用 position_import_review 复核。只有用户明确说确认后才调用 position_import_confirm。部分截图用 merge；完整账户快照才用 replace。

生成计划前，读取 position_snapshot，收集带日期和来源链接的市场与个股分析、当前价格和有效止损，再调用 position_rebalance_plan。跨插件协作时用 summary，单独分析时用 detailed。解释总仓位变化、每只持仓动作、试探仓风险金额、失效规则、条件增仓触发条件和未分配额度。

所有工具输出都是研究计划，不是下单指令。禁止声称已成交；实际成交后请用户更新持仓快照。试探仓失效时按预设规则退出，不向下摊平；条件增仓未触发前不得当作可执行仓位。
```

## 开发与安装

- Node.js 24 或更新版本；DSHA 插件运行时提供 `@deepseek-ai/dsh-mcp-client`。
- 插件入口：`lib/index.js`；工具定义：`lib/tools.js`；仓位约束算法：`lib/planner.js`；SQLite 存储：`lib/storage.js`。
- 导入 ZIP 前请确认 DSHA 版本支持包内 `.codex-plugin/plugin.json` 和 `cordis.patch.yml` 格式。
